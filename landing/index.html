线性管道

Task 即最小编排单位，
runner 严格串行。

一次 Task 就是一条完整管道：部署被测服务、前置门检查、正式测试、幂等拆除。 没有隐藏阶段，没有并发分叉——隔离由拓扑保证，事实由产物说话。

核心特性

为人类与 Agent 共同设计。

UI 给人看，API 给 Agent 用，语义完全对等。一份 OpenAPI 3.1 契约是唯一规格来源。

⇄

声明式 Runner 契约

runner.yaml + 镜像 + exec-form entry。输入走落盘 params.jsonl，产物三选一：result.json / html / csv。Runner 能脱离平台独立运行。

⚡

exports 信息传递

runner 向 exports.env 写 KV，平台词法收割、按管道序注入下游。AG_SERVED_URL 等公共参数由 deploy 导出或静态声明，Runner 不感知 Endpoint。

⟲

Task 级重试

重试 = 整 Task 全量重跑含 fresh deploy，杜绝 warm cache 污染测量。attempt 单调递增，(task_id, attempt, seq) 精确定位每次执行。

☸

K8s 原生执行

唯一执行后端是 K8s Job，每 runner 一个、幂等键去重。Genet 负责服务部署生命周期，平台不直连集群。

◉

Agent 友好

OpenAPI 3.1 机读契约、llms.txt、结构化错误码。Agent 可以直接提交 Task、读结果、写 Runner——和人类走同一个接口。

▤

控制台 Web UI

shadcn/ui 桌面优先控制台：Task 列表、详情、报告、日志、提交全链路覆盖，文件产物以页面内弹窗呈现。

运行模式

两种接入方式，同一条管道。

deploy 模式

平台拉起被测服务

提交 deploy 配置，平台自动前置 service-deploy、追加 service-clean。评测一个还未上线的服务。

  • service-deploy 调 Genet 起 Helm release
  • deploy-state.json 周期报告排队与就绪
  • exports 自动注入下游所有 runner
  • clean 在成功 / 失败 / 取消 / 超时全路径执行
外接模式

评测已有 Endpoint

提交静态 service 块指向已运行服务，无部署开销，专注测试本身。与 deploy 二选一，互斥校验。

  • service.url + model 直接声明
  • 无 deploy / clean runner，管道更短
  • 同一套 AG_SERVED_* 公共参数投影
  • 适合回归评测与对比基准
Runner 生态

已就绪的 Runner。

Registry 目录发现 + content_sha 指纹 + name@version 不可覆盖。deploy / clean 角色拒绝注册。
